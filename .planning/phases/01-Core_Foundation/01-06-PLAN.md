Purpose: Satisfy D-01 (physical device output control) and F1 (XInput controller support) for rumble feedback.

Output: Modified gilrs_backend.rs with xinput_ffi module, two new fields on GilrsBackend, xinput_idx population in poll(), and XInput dispatch branch at the top of send().

```rust
    fn send(&mut self, device_id: &str, pin_id: &str, signal: Signal) {
        // ── XInput path: dispatch via XInputSetState ──────────────────────────
        if let Some(&xinput_slot) = self.xinput_idx.get(device_id) {
            let byte = match signal {
                Signal::Float(f) => (f.clamp(0.0, 1.0) * 255.0) as u8,
                Signal::Bool(b)  => if b { 255 } else { 0 },
                _ => return,
            };
            let entry = self.xinput_rumble.entry(xinput_slot).or_insert((0, 0));
            match pin_id {
                "rumble_strong" => entry.0 = byte,
                "rumble_weak"   => entry.1 = byte,
                _ => return, // other pin names are not XInput rumble
            }
            #[cfg(windows)]
            unsafe {
                use xinput_ffi::*;
                let vib = XINPUT_VIBRATION {
                    // 0-255 byte mapped to 0-65535 motor speed: multiply by 257 (= 0xFFFF / 0xFF).
                    w_left_motor_speed:  (entry.0 as u16).saturating_mul(257),
                    w_right_motor_speed: (entry.1 as u16).saturating_mul(257),
                };
                XInputSetState(xinput_slot, &vib);
            }
            return;
        }

        // ── PS/Switch HID path via GyroManager (unchanged) ───────────────────
        let (vid, pid, idx) = match self.lookup_phys(device_id) {
            Some(t) => t,
            None => return,
        };
        let byte = match signal {
            Signal::Float(f) => (f.clamp(0.0, 1.0) * 255.0) as u8,
            Signal::Bool(b)  => if b { 255 } else { 0 },
            _ => return,
        };
        self.gyro.set_output_byte(vid, pid, idx, pin_id, byte);
    }
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| sink_bus (processing thread) -> GilrsBackend::send() (I/O thread) | Float/Bool signals cross thread boundary via RwLock; values feed directly into XInputSetState motor speeds |
| xinput_idx map -> XInputSetState slot argument | Slot index 0-3 is derived from kind_seen counter; an out-of-range or stale index passed to XInputSetState is rejected by the driver with ERROR_DEVICE_NOT_CONNECTED |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | xinput_rumble cache | accept | Cache holds 0-255 u8 values clamped from Float signals; no external input reaches this map except from the internal sink_bus |
| T-06-02 | Denial of Service | XInputSetState at 500 Hz | accept | XInputSetState is a very cheap Win32 call; Microsoft documentation confirms it is safe to call every frame; no queuing or blocking occurs |
| T-06-03 | Elevation of Privilege | unsafe XInputSetState block | mitigate | Block is `#[cfg(windows)]` only; XINPUT_VIBRATION struct is `#[repr(C)]` with no padding or pointer fields; slot index is u32 derived from internal counter, not from user input |
| T-06-04 | Information Disclosure | xinput_idx HashMap contents | accept | Map contains only device_id strings (non-sensitive) and slot indices; no PII or credentials |
| T-06-05 | Spoofing | GilrsBackend device_id matching | accept | device_id format `gilrs:xinput:N` is constructed internally from gilrs enumeration; external users cannot inject device IDs into the backend |
</threat_model>
